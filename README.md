# Читай — навчальна книгарня з SQLite

Лабораторна №4 з основ програмної інженерії. Цвіркунов Олексій Дмитрович, ІПЗ-21. Індивідуальне виконання; внески інших учасників не імітуються.

Продовження [Flask-проєкту ЛР03](https://github.com/73ts23-prog/opi-lab03-flask-library). Додано базу даних, відгуки, кошик, замовлення й захищену адмін-панель. Усі ціни, покупці та замовлення в прикладах навчальні; оплати й реальної доставки немає.

## Можливості

- SQLite: сім таблиць, зовнішні ключі та транзакції.
- CRUD відгуків; створення й редагування товарів та клієнтів.
- Кошик зі зміною кількості, залишки товарів і замовлення з позиціями.
- Статуси: нове → в обробці → відправлено → виконано; дозволене скасування повертає залишок один раз.
- Додаткові функції: пошук українською, фільтри жанру й ціни, промокод `READ10` на 10%.
- Адміністративний вхід із хешованим паролем і CSRF-захистом форм.
- Захист від повторного оформлення, підміни підсумку з форми та перезапису залишку застарілою адмін-формою.

## Встановлення у Windows

Потрібен Python 3.12 або новіший. У PowerShell у папці проєкту:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m flask --app app init-db
python -m flask --app app create-admin
python app.py
```

Команда `create-admin` просить логін і власний пароль від 10 символів. Введення пароля приховане; стандартного пароля в репозиторії немає. Якщо логін уже існує, можна створити адміністратора з іншим логіном.

Сайт: [http://127.0.0.1:5004](http://127.0.0.1:5004). Адмін-панель: [http://127.0.0.1:5004/admin](http://127.0.0.1:5004/admin). Зупинка — `Ctrl+C`.

Якщо активація середовища недоступна, запускайте його Python напряму:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m flask --app app create-admin
.\.venv\Scripts\python.exe app.py
```

Для macOS/Linux активація: `source .venv/bin/activate`; решта команд ті самі. Після встановлення залежностей Windows також може запускати `Запустити.bat`.

## Дані й поведінка

База створюється як `instance/db.sqlite`, локальний ключ сесій — `instance/secret.key`. Папка `instance/` не публікується. Для відтворення достатньо `schema.sql` і початкової добірки в `models.py`: порожня БД автоматично отримує шість книжок і `READ10`. Повторна ініціалізація не видаляє й не повертає приховані записи.

Товари прибираються з каталогу логічно (`active=0`), щоб зберегти ID у старих кошиках та історію. Їх можна повернути через редагування. Відгуки й клієнти без замовлень видаляються фізично; клієнта із замовленнями видалити не можна.

Ціни зберігаються в копійках. Кожна позиція замовлення містить знімок назви й ціни. Подальше редагування каталогу не переписує оформлене замовлення. Якщо інший запит уже змінив товар, застаріла форма редагування відхиляється — потрібно оновити сторінку.

Квитанція доступна лише браузеру, який оформив замовлення. Це гостьовий сценарій без клієнтських акаунтів і без історії між різними пристроями.

## Структура

- `app.py` — фабрика застосунку, конфігурація, CLI та загальні сторінки.
- `models.py`, `schema.sql` — з’єднання, схема, CRUD, замовлення й статуси.
- `validation.py` — перевірка тексту, email, кількості та цін.
- `routes/admin.py` — вхід і керування таблицями.
- `routes/shop.py`, `routes/feedback.py` — каталог, кошик, оформлення та відгуки.
- `templates/`, `static/` — шаблони, локальні стилі та меню.
- `tests/` — 35 автоматичних перевірок з окремими тимчасовими БД.
- `lab-reports/` — звіти та справжні скріншоти.

## Перевірка

```console
python -m unittest discover -s tests -v
```

Перевірено справжні CRUD-запити, FK, збереження після перезапуску, CSRF, доступ до адмін-панелі, залишки, відкат транзакції, повторне оформлення, промокоди та застарілі форми. Браузерний сценарій пройшов від пошуку до зміни статусу; перевірено ширини 375, 390, 768, 1024 та 1440 px. На мобільному адмін-таблиці прокручуються у власній області. Фізичний iPhone не тестувався.
